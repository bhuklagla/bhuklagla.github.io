# Website planning

Read `docs/WEBSITE_BRIEF.md` from the repository root. Preserve confirmed decisions and ask about the next consequential choice instead of reopening them. The confirmed journey is menu browsing followed by Zomato ordering.

Discuss audience, brand personality, page structure, languages and menu presentation in manageable steps. Inspect existing approved brand assets before suggesting colours. Treat old handoffs as context and verify publication facts separately. Do not choose a framework or generate website code merely to illustrate a discussion.

When visual exploration is requested, read `.claude/skills/frontend-design/SKILL.md`. Use `.claude/skills/ui-ux-pro-max/SKILL.md` for supporting research; its helper is `.claude/skills/ui-ux-pro-max/scripts/search.py`. Preset themes from `.claude/skills/theme-factory/` are optional. Keep the approved brand identity and the user's decisions primary.

Record decisions and unresolved points in the brief. Begin implementation only when the user asks to build after discussion; then document the chosen architecture and commands as they actually exist.
